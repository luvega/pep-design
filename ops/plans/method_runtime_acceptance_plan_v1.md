## 当前目标和通过标准

全部 10 种方法按各自输入输出要求完成一个有边界的小规模真实原生任务。
通过须有可重放的代码、权重、环境、输入、执行日志、原生终点及可解析输出；
只有安装、import、parser fixture 或进程退出 0 不足以通过。不同方法不要求
统一靶点、统一产物或多 seed。复用完整证据，仅为真正缺项补跑。

运行验收与候选质量分开记录。既有结构/序列/手性检查和原生过滤结果保持原样，
质量失败不再阻塞当前代码与环境验收，也不能据运行通过称质量合格。
不新增模型运行，不为修复质量而用尽剩余计算预算；大规模比较留待后续单独计划。
按 grilling 已确认的“阶段内自主执行，关键变化再讨论”实施，不重复确认已有决定。

## 用户选定的资源上限

仅使用现有本机与独立受控环境。必要的依赖安装及公开来源资产下载纳入以下
预算，使用现有合法资产优先；不将容量视为无上限授权。

| 资源 | 阶段硬上限 |
|:---|:---|
| 新增 GPU 运行 | 累计 24 GPU 小时 |
| CPU 密集任务 | 累计墙钟 24 小时；并发总量最多 24 线程、256 GiB RAM |
| 新增下载 | 累计 50 GiB |
| 新增磁盘占用 | 200 GiB |
| 每方法新尝试 | 最多 3 次，含首次；旧 attempt 不重用、不重置 |

为便于核算，GPU 方法任务按占用 GPU 的任务墙钟累计，CPU 密集任务按各任务
墙钟之和累计；失败任务同样计入。方法执行启动即消耗一次 attempt，基础设施
启动失败也计入；前检修正不创建 attempt。下载重试流量计入累计下载额度。
安装或前检不构成方法通过。每次任务启动前
根据剩余额度配置超时和资源限制；额度不足不启动。原始日志、结构、依赖、
权重与大文件留在 gitignored 外部目录，小型来源/结果摘要进入项目。

出现预算耗尽、需要额外尝试、用途许可/访问条件无法满足、需改变原生算法或
本阶段范围时，记录具体阻断、已做诊断与可选下一步，返回用户讨论；其余独立
方法继续在预算内推进。任何未通过方法不计入通过数，不能宣告 10/10 完成。

## 交付与边界

交付包括 10 方法验收矩阵、可重放原始证据索引、逐方法 QC/原生过滤结果、
失败记录、环境与执行配置，以及阶段资源账本。目标是 10/10 达到上述方法级
标准；若额度内仍有阻断，交付真实进度和阻断清单，另行决定调整。

本阶段不等于公平 Benchmark、方法排名、亲和力或生物学验证，也不冻结目标集。
候选质量按各方法的可检查原生范围表述，计算代理指标不能证明实验有效。
原执行失败、来源保护、Git 授权和版本规则继续有效；不 commit/push，
`VERSION=1.2.21`，不自动准备新 release 或替用户写 signoff。

整体理解已确认，按当前运行范围与原限额自主实施；本次范围修订不启动新增执行。

SaLT&PepPr 的本阶段用途已由用户另行明确：仅作非商业方法评测，与药物开发无关，并接受现存许可条款。用途记录与许可摘要绑定见 [阶段用途确认](../../benchmark/deployment/method_acceptance_use_scope_v1.json)。用途确认本身不是运行证据；原生流程的实际完成情况见下列验收报告，历史许可待确认记录保留。
